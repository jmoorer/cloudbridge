# CloudBridge — AGENT.md

## Project Overview
Unified cloud storage manager that aggregates Google Drive, Dropbox, and OneDrive into a single interface. Users can browse, search, pin, and transfer files across providers.

## Stack
- **Framework**: TanStack Start (file-based routing, SSR, server functions)
- **Auth**: Better Auth (OAuth + session management)
- **Database**: Turso (SQLite edge DB) via Drizzle ORM
- **UI**: Tailwind CSS + shadcn/ui
- **APIs**: Google Drive API, Dropbox API, Microsoft Graph API (OneDrive)
- **Deploy**: Vercel

## Key Conventions

### Server functions
All provider API calls go through TanStack Start server functions in `app/server/fns/`. Never call provider APIs from the client directly — secrets must stay server-side.

```ts
export const listFiles = createServerFn({ method: 'GET' })
  .validator((data: { folderId?: string }) => data)
  .handler(async ({ data, context }) => { ... });
```

### Parallel provider fetching
Always use `Promise.allSettled` (not `Promise.all`) when fetching from multiple providers so one failing provider doesn't break the entire response.

```ts
const results = await Promise.allSettled(
  accounts.map((account) => fetchFromProvider(account, folderId))
);
const files = results
  .filter((r) => r.status === 'fulfilled')
  .flatMap((r) => r.value);
```

### Unified FileItem type
All provider responses must be normalised into this shape before leaving the server function:

```ts
type FileItem = {
  id: string;
  name: string;
  mimeType: string;
  provider: 'google' | 'dropbox' | 'onedrive';
  size?: number;
  modifiedAt?: Date;
  isFolder: boolean;
  webUrl?: string;
};
```

### Token refresh
Before calling any provider API, check `expiresAt` on the stored token. If expired or within 5 minutes of expiry, refresh and re-upsert before proceeding. Each provider client (`google.ts`, `dropbox.ts`, `onedrive.ts`) handles this internally.

### Auth route
`app/routes/api/auth/$.ts` is a Better Auth catch-all. Do not add logic here — configure behaviour in `app/lib/auth.ts`.

### Database
- Use query helpers in `app/lib/db/queries.ts` — do not write raw Drizzle queries in route/component files.
- Schema changes: edit `schema.ts` → `npx drizzle-kit generate` → `npx drizzle-kit migrate`.
- Never delete migration files.

## Provider OAuth Scopes

| Provider | Scope |
|---|---|
| Google | `openid email profile https://www.googleapis.com/auth/drive.readonly` |
| Dropbox | `files.metadata.read files.content.read` |
| OneDrive | `openid profile email Files.Read offline_access` |

## Build Order (phases)
1. **Auth + DB** — Better Auth, Turso schema, migrations ✅
2. **Google Drive** — OAuth connect, token storage, file listing, file tree UI
3. **Multi-provider** — Dropbox + OneDrive OAuth, unified listing, provider badges
4. **Core features** — Cross-provider transfer, search, pinned files, storage stats
5. **Polish** — File preview, mobile layout, empty states, error boundaries, deploy
